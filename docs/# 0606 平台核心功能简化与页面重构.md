## 一、产品简化大原则
### 1.1 功能做减法：砍掉审核
**现状/背景：**  
目前系统功能较繁琐，运营 NOC 侧认为业务部门界面操作太复杂，希望大幅简化。

**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 审核功能 | 全部砍掉，所有模块都不要审核 | 包括指标管理、巡检、知识库等 |
| 运营侧可见功能 | 只保留他们需要的，其余隐藏或删除 | 映射、底座等对内合理<br/>但对运营侧不需要 |
| 核心保留 | 血缘画布、配置规则、配置标签规则 | 其余围绕 PPT 范围来 |


**关键结论：**

+ 暂时**全部不要审核功能**，新增/修改/维护一律免审。
+ 对运营 NOC 侧：**不需要看到的功能全部删掉**，他们只需要自动化的结果。
+ 大屏侧的指标新增/变更，期望**自动同步到图谱**，而非手动操作。
+ 指标管理只保留四大核心：指标挂靠、**血缘画布、配置规则、配置标签**。

**待办：**

- [ ] 梳理现有功能清单，标记运营侧需删除的模块 —— 优先级：**高**
- [ ] 砍掉所有审核功能的入口和逻辑 —— 优先级：**高**

### 1.2 主题与体验
**现状/背景：**  
下周需向业务部门做 demo 演示，对视觉效果和人性化操作要求较高。

**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 主题切换 | 支持深色/浅色切换 | 演示时优先用深色（蓝黑） |
| 画布适配 | 切换主题后，血缘画布等图表需跟随调整颜色 | 需确认技术可行性 |


**关键结论：**

+ 支持主题切换（深色/浅色），演示要用深色。
+ 画布图表颜色需跟随主题联动调整。
+ 整体方向：**效果要高级、信息要精简、操作要人性化**，不要传统列表化管理那种繁琐感。

**待办：**

- [ ] 实现深色/浅色主题切换，画布颜色联动 —— 优先级：**中**

## 二、指标树与标签集管理（核心页面设计）
### 2.1 指标树新概念
**现状/背景：**  
原系统有标签和指标配置，但缺少「指标树」概念。现在需要新增一个可无限层级维护的树形结构，与指标定义字段（一级/二级屏）无关。

**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 指标树 | 新增无限层级节点维护能力 | 可无限往下扩展，示例只看到三级 |
| 标签集 | 原有功能，也支持无限层级 | 一个指标可挂多个标签 |
| 分权分域 | 不同部门（财务部、市场部等）各自维护自己的指标树和标签集 | 张三进财务部只看到财务部的树和标签 |
| 规则配置 | 运营 NOC 统一控制所有规则，与权限无关 | 规则全局生效 |


**关键结论：**

+ 指标树是**全新概念**，部门级维护，相互不干扰。
+ 分权分域：账号登录后自动切换到对应部门的指标树和标签集。
+ 只有部门范围内的指标，才能拖入该部门的树/标签集并配置规则。

### 2.2 页面布局与交互设计
**现状/背景：**  
用户强烈要求把「维护指标树、维护标签集、指标挂靠、配置规则」整合在一个页面内完成，要求人性化、操作简便，类似 VS Code 的拖拽体验。

**核心讨论点（布局演进）：**

| 版本 | 布局方案 | 问题/结论 |
| --- | --- | --- |
| 初版 | 左右两栏 + 中间详情 | 不够聚焦 |
| 第二版 | 左(指标树)+下(标签集) / 中间(指标) / 右(待选指标) | 待选指标拖到树或标签集，操作少一步 |
| 最终版 | **中间放指标，四周放需要挂靠的东西** | **拍板确定**：以指标为核心，拖拽到树/标签集/规则 |


**关键结论：**

+ **最终布局：中间 = 指标（待选），四周 = 指标树（左上）、标签集（左下）、规则（右侧）**
+ 待选指标从中间拖到左上侧树或左下侧树或右上侧树或右下侧树完成挂靠。
    - 四个树分别为标签树、指标树、规则树、xx树（待定）
    - 标签集与指标树的区别：
        * 标签是多对多，一个指标可复制到多个标签下；
        * 指标树是一对一归属。
+ 树本身维护（调整层级）通过小窗口上方的加号完成添加，与指标拖拽分开（新增节点）
+ 默认进入页面可展示部门现有指标数、标签数等概览。
+ 中间区域选中指标后，展示未挂靠指标的核心信息（口径、维度等）。

**待办：**

- [x] 生成指标树+标签集+指标关联页面的文字版/示意版设计稿—— 优先级：**高**
- [ ] 确认拖拽交互细节（防止误操作，如拖出确认弹窗）—— 优先级：**高**
- [ ] 标签集与指标树的数据结构及复制/移动逻辑 —— 优先级：**高**

## 三、知识库管理与血缘画布
### 3.1 知识库管理
**现状/背景：**  
原知识库有审核流程，现需简化。

**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 审核 | 砍掉 | 有权限的人直接录入、维护 |
| 维护单位 | 文件级别 | 业务部门方案可能迭代（1.0→1.2→1.3） |
| 版本替换 | 新文件导入后，审查相似度，直接替换原文件对应部分 | 自动更新 |
| 删除 | 删除文件 → 知识库对应信息同步删除 | 逻辑与之前一致 |


**关键结论：**

+ 知识库**不要审核**，有权限的人直接维护。
+ 维护粒度是**文件级**，支持版本替换和增量更新。
+ 具体调用方式和业务逻辑，还需要进一步调研确认。

**待办：**

- [ ] 调研知识库实际调用方式和业务逻辑（找相关人确认）—— 优先级：**中**
- [ ] 实现知识库文件级维护+版本替换 —— 优先级：**中**

### 3.2 血缘画布
**现状/背景：**  
现有血缘画布效果已经很好，基本可沿用，但需简化操作。

**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 预览 vs 首页 | 目前区分不清晰 | 需重新梳理逻辑 |
| 聚焦逻辑 | 选中一个指标 → 展示与该指标所有关联关系 | 未点具体关系前，全部列出 |
| 添加关系 | 非拖拽，而是选中后人性化快捷添加 | 如选中指标→点添加关系→自动带入源/目标 |
| 预览功能 | 价值存疑，可能先不要或合并 | 需再评估 |


**关键结论：**

+ 血缘画布**基本沿用现有实现**，内容契合。
+ 核心逻辑：选中指标 → 列出所有关联关系 → 点具体关系可聚焦/高亮。
+ 添加关系走**人性化快捷路径**（非拖拽），如选中指标后点「添加关系」自动带入。
+ 预览功能的价值需再评估，可能先砍掉或合并。
+ 如果加上深色主题，视觉效果可能会更好。

**待办：**

- [ ] 梳理血缘画布「首页→聚焦→添加关系」的逻辑，砍掉/合并预览 —— 优先级：**中**
- [ ] 优化添加关系的快捷交互 —— 优先级：**低**

## 四、分析报告管理
### 4.1 功能定位与框架
**现状/背景：**  
原「巡检」功能需改造成「分析报告管理」，作为系统第四个主菜单。

**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 菜单结构 | ① 指标管理 ② 知识库管理 ③ 血缘画布 ④ 报告管理 | 原巡检隐藏或改名 |
| 报告计划 | 报告名称、执行周期、筛选范围 | 类似巡检计划 |
| 筛选范围 | 指标树层级 + 标签 → 取并集 | 跨域可选，不限制分权分域 |
| 手动加指标 | 简化，不要太麻烦 | 辅助手段 |
| 剔除规则/关系 | 报告里不需要某些规则或传导关系时可剔除 | 新增能力 |


**关键结论：**

+ 分析报告 = 原巡检的升级版，核心框架类似。
+ 筛选范围支持「选指标树层级下的所有指标」+「选标签下的所有指标」取并集。
+ 报告配置环节**放开分权分域限制**，可跨部门选指标（因为分析有跨域关联）。
+ 可手动剔除不需要纳入报告的关联关系。

### 4.2 报告模板与版本
**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 模板 | 既有模板列表，也支持提示词生成模板 | 生成后可持续复用 |
| 模板与筛选串联 | 选完筛选条件后，再选/生成模板，最后生成报告 | 功能需串成完整流程 |
| 报告版本 | 同一计划多次执行产生不同版本（0.1→0.2→0.3） | 修改计划或知识后重跑即新版本 |
| 版本管理 | 无需业务部门审批回退，直接版本化管理 | 简化交互 |


**关键结论：**

+ 报告生成前：先筛选指标 → 再选/生成模板 → 最后出报告。
+ 报告支持**版本管理**，修改计划/知识后重跑自动生成新版本。
+ 报告样式先不 care，后续会提供现有 React 报告代码直接沿用。

**待办：**

- [ ] 分析报告页面设计（基于巡检改造）—— 优先级：**高**
- [ ] 报告模板管理+提示词生成功能 —— 优先级：**中**
- [ ] 报告版本管理逻辑 —— 优先级：**中**
- [ ] 获取现有 React 报告代码 —— 优先级：**中**

### 4.3 反哺机制
**现状/背景：**  
报告生成后，用户发现指标关系或知识有误，希望能从报告直接反推修改。

**核心讨论点：**

| 维度 | 内容 | 备注 |
| --- | --- | --- |
| 反哺入口 | 报告中的关系图或指标分析区域 | 具体位置看报告样式 |
| 反哺内容 | ① 修改关联关系（增删改）② 更新知识库知识 | 两个方向 |
| 反哺后 | 修改后重新跑报告，生成新版本 | 版本递进 |


**关键结论：**

+ 反哺入口：如果在关系图上，可点按钮/图标去修改关联关系；如果在指标分析区，可点按钮去更新知识。
+ 也可考虑**统一入口**：在异常分析处点一个按钮，两侧展开「改知识」和「改关系」。
+ 反哺后重新跑报告，版本自动递进（如 0.3→0.4）。
+ 实际交互效果让 AI 发挥，先做文本框/弹框形式，后续再优化。

**待办：**

- [ ] 设计反哺入口的交互方式（弹框/侧边栏/统一入口）—— 优先级：**中**
- [ ] 打通反哺→知识库更新/关联关系修改→重新生成报告的链路 —— 优先级：**中**
